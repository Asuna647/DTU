  | Frontend | React + TypeScript | High-contrast, large-button UI tailored for

  | LLM Layer | Claude / GPT | Serves strictly as an Explanation Layer.
  Translates rule engine results into simple, warm Hindi/English text. |

  3. Data Flow Workflows

  A. Voice Query Flow

  1. User taps mic button and speaks: "Mujhe pension ke baare mein batayein"
  2. Frontend sends query to /api/voice-query
  3. Speech Service detects intent (pension_inquiry, confidence: 0.9)
  4. Returns guided Hindi response + Audio narration trigger + Suggests document
     scan

  B. Document Scan & Eligibility Flow

  1. User uploads/scans Aadhaar card
  2. OCR Service extracts text via Tesseract/Regex (Name: Ramkali Devi, Age: 72,
     BPL: Yes)
  3. Backend passes extracted data to /api/check-eligibility
  4. Rule Engine evaluates:
     - Rule 1: Age = 72 ≥ 60 ✅
     - Rule 2: Has BPL Card = Yes ✅
  5. Returns verdict: ELIGIBLE for IGNOAPS Pension along with a 4-step action
     roadmap.

  4. Why This Architecture Prevents Hallucinations

  Unlike generic AI chatbots that guess eligibility rules, Digital Saarthi
  decouples decision-making from explanation:

  [Uploaded Document] → [OCR Extraction] → [Hardcoded Rule Engine] → [Verdict: 
  Eligible]
                                                                          │
                                                                          ▼
                                                           [LLM Explains Verdict
  in Hindi]

  - Rule Engine: Makes all eligibility decisions objectively (deterministic).
  - LLM: Only translates the verified output into simple language. It cannot
    invent or change rules.
